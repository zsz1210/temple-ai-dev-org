# Bounded Lean operation: common obligations

Use only when `context enter --material operation` reports `procedure_selection.status`
as `selected`. Read this file and the returned current-stage module completely.
The combined lean-execution procedure is then a reference, not an extra read.
Fallback, recovery, Standard, High-Assurance, UI, unclear scope, overlapping
ownership or active runtime workers use the existing route. No profile downgrade,
implementation, spending or external authority is granted by entry.

Read the returned route, complete required bodies and remaining required references.
Native provider instructions and bootstrap remain mandatory. Reuse only material
actually read, still available and unchanged; digests prove neither reading nor
comprehension. Explicit independent whole-source requirements take precedence.

Entry never claims work. Claim with the eligible Identity, Principal and current
base revision before mutation. Reacquire after changed state or authority. Entry's
digest is not a finish preview or permission. Keep product work separate from
lifecycle commands. Expanded scope stops this narrow route and requires replanning.

Finish accepts read-only `--dry-run` and its own `--expected-plan`. Inspect both
mutation and diagnostics. Reuse full Status/Doctor results only for the unchanged
scope they checked; do not rerun them merely to repeat the report. Reference a
current evidence record instead of creating duplicate narratives.

Applied lifecycle writes with failed diagnostics are neither rollback nor success.
Preserve attention even for terminal work. Inspect state and use the identical
finish request to repair diagnostics only if candidate, evidence and authority
still match. Historical receipts are not fresh verification. For an interrupted
journal, inspect before replaying the identical request; never change the operation
ID's facts, delete recovery state or bypass it with individual mutations. Read
[Assurance and recovery](assurance-and-recovery.md) when recovery is needed.
Stop at the named stage and next owner; no merge, publication or new task is implied.
