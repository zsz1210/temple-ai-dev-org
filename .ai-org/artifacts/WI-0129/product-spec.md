# WI-0129 product specification

## Reader outcome

A person evaluating Temple can understand its purpose, current capabilities, delivered milestones, current qualification stage, and future direction without reading internal Work Item history. A first-time operator can then follow one short Core Path instead of reconstructing the journey from the reference manual.

## Approved scope

- Maintain English, Japanese, and Traditional Chinese Roadmaps with the same product-level structure.
- Add one canonical English Core Path and route the documentation index and Usage guide to it.
- Correct the `no-go` lifecycle statement, add ordinary sequential claim/release guidance, and place Capability, Context, and Execution Route resolution at the point of work.
- Add one future experiment design that separately measures Temple process effect and Adaptive Execution Route effect.
- Preserve the blocked release Work Item and all previous validation records without rewriting their outcomes.

## Acceptance criteria

The Work Item acceptance criteria in `.ai-org/work-items/WI-0129.json` are authoritative. In particular, the experiment must allow positive, neutral, negative, and inconclusive outcomes and must state what Temple will simplify or remove when measured value does not justify overhead.

## Excluded behavior

No runtime code, project policy, model mapping, Provider execution, live experiment, Management Console, external integration, or public-distribution state changes in this Work Item.
