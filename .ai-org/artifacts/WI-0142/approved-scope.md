# WI-0142 approved scope

## Problem

WI-0141 produced useful diagnostic evidence, but every turn contained one unknown acquisition record and cache behavior varied materially between repetitions. Those gaps prevent complete route-adherence proof and routing-only Token claims. The experiment design also exists mainly as one specialized harness, which makes later workflow or new-model evaluation harder to repeat consistently.

## Acceptance criteria

1. Sanitized App Server action fixtures classify an exact control-package read without retaining raw commands or output.
2. Unsafe, ambiguous, escaping, failed, and over-limit acquisition records still fail closed.
3. Deterministic analysis reports gross input, cached input, non-cached input, output, Operational Tokens, cache share, and repetition spread separately.
4. Cache-control validity is explicit and blocks causal efficiency claims when the protocol did not control cache state.
5. A reusable guide and protocol template cover process-only, model-only, and deliberately designed factorial comparisons.
6. The guide requires a frozen protocol, representative tasks, objective quality gates, order control, cache control, data-derived limits, exact approval, zero unplanned retry/fallback, privacy boundaries, and limitation-aware reporting.
7. No Provider generation occurs and `.ai-org/artifacts/WI-0141/` remains unchanged.

## Non-goals

- retroactively changing the retained WI-0141 observation or report;
- claiming that the historical unknown reads are proven control reads;
- choosing or recommending GPT-6 before its real Provider contract is available;
- adding automatic model routing or a generic model-execution command;
- treating one experiment's sample count or Token ceiling as a framework default.
