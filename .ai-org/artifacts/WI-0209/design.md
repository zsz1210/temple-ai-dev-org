## Design findings

1. An unknown item was sanitized to null before diagnosis. Preserve only a schema-defined type label, a bounded unknown/missing category, and rejection rule. Never retain payload, reasoning or raw unknown names. Keep disallowed tools fail-closed; do not speculate about WI-0208's original type or permit all schema-valid tools.
2. Installed configuration exposes ambient MCP servers and multi-agent tools despite a prompt saying not to use them. Bind process-local disable overrides for external capabilities and validate the effective configuration before any actor turn. Do not change user configuration, credentials, global installed integrations or subscription authentication. This changes the common instrument equally for all arms and does not identify the earlier trigger.
3. Nested pair runtime scratch was included in the new matrix's whole-lab seal although the underlying pair contract calls it unsealed operational scratch. New evidence scope explicitly excludes only the six exact top-level subject-N.runtime directories, all .git metadata as before, and seal/manifest self-reference. Do not exclude arbitrary similarly named directories or any subject product/evidence files. Persist a per-file manifest, take two equal snapshots after confirmed provider exit, and independently recompute after sealing. Detect mutation; never repair an old seal or silently retry a consumed model run.
4. Readiness JSON parsing hid command status. Validate exit code, stdout type/presence and parse success separately; preserve bounded sizes/error categories, not raw sensitive stderr. Distinguish a command deadline from transport timeout. Keep the same model/time budget.

## Review corrections

Independent review requires explicit pinned-map membership as well as disabled values: empty, absent, null, array or string tool maps cannot prove isolation. This was reproduced and corrected before any model turn. The installed CLI interprets `-c` paths as dot-separated strings rather than TOML quoted keys; only simple discovered identifiers are supported, with unsupported names rejected. A generation-free effective-config check verified three MCP servers and 25 plugins disabled. The isolation profile is derived by reading local TOML files without launching a Provider; source hashes are checked before every dedicated Provider start. Preexisting read-only discovery is not claimed to undo earlier app startup.

Confirmed shutdown means the owned app-server child exited, not proof that every descendant exited. Exact durable evidence is hashed twice and verified again from its per-file manifest. Runtime scratch is retained separately from this scope. Historical default pair behavior and WI-0208 are unchanged; new safeguards are opt-in to this new instrument.
