# Small-task operating contract and comparison readiness

The maintainer authorized implementation through readiness for another comparison.
This scope includes instruction authoring, installed offline checks, independent
assurance and a finite comparison proposal. It does not authorize new model calls,
reuse of old approvals, merge, publishing, Credits, reset or a policy downgrade.

Baseline: `4c606f7113600caeec04daf29477daa17b07409c` (WI-0237), not main or a
private experiment ancestor. Historical WI-0234/WI-0236 evidence stays frozen.

## Treatment

Replace repeated global prose across native AGENTS, TEMPLE, Work Skill and its Lean
recipe with one complete compact operating contract and explicit triggered detail.
Native instructions still route to the whole TEMPLE contract before governed work;
current required project instructions cannot be silently replaced or summarized.
The Work Skill owns command/stage mechanics; specialized existing or new references
own only conditional details. Retain a traceable obligation map before accepting
the change. This changes authored obligations, not JSON presentation or model.

Use existing claim and one finish operation. State once that one evidence record
may support multiple named gates and that generated handoff/diagnostic facts need
not be rewritten. Do not remove actual evidence or semantic judgment. The earlier
one-finish mechanism is not claimed again as a new reduction in CLI calls.

Preserve profile/risk floors, distinct Verifier and Independent QA identities,
scoping, protected ownership, authority/spec revision binding, uncertainty stops,
bootstrap, recovery, external-write approval and project-owned instructions.
Do not add a Position, execution engine, session cache or automatic role change.
Runtime-reuse and historical-scope coordination are separate future mechanisms.

## Acceptance

1. Map every prior obligation to a retained entry or named triggered source;
   review read-only, Lean, Standard, High-Assurance, UI, tracker, bootstrap,
   changed-scope and uncertain-recovery scenarios. A text-match check alone is not
   semantic verification.
2. Fresh installs deliver whole new sources. Upgrade preserves project-owned
   instructions, rejects managed drift, and retains explicit whole-source rules.
3. Same fixture facts, policy, actor identities, runtime and entry format: measure
   source-body and serialized bytes separately. No silent truncation or statement
   that smaller bytes prove lower provider Tokens. Document actual removed work.
4. Real claim/product-test/finish paths and negative controls pass. Focused tests
   aid editing; run full verification on the final behavior and distinct QA.
5. Prepare a matched old-Temple/new-Temple/ordinary diagnostic using the repaired
   evaluator and identical product acceptance. Freeze provenance, order, measures,
   finite ceilings and stops. No automatic retries, fallback or sample expansion.
   Readiness without actual generation is not a performance result.

The practical next decision is whether to retain this simpler authored contract:
an authority or acceptance regression rejects adoption; measured complete-attempt
cost and time inform the remaining tradeoff. Small diagnostic samples cannot
establish population effects. Do not invent an effect threshold from byte counts.

Stop after a reviewable candidate, offline evidence and runnable, unconsumed
comparison preparation. If a boundary cannot be preserved, retain the old behavior
and report that exact unresolved decision instead of repeatedly running models.
Rollback is a reviewed reversal of this instruction treatment, not deletion or
rescoring of old experiments. No production or external release is involved.
