# WI-0229: exact-text completion

The maintainer authorized completing the small-task design, implementation and
verification without repeated phase approvals. Implement the separately proposed
WI-0225 mechanical exception, not a new Position or default workflow. Use Standard
delivery and distinct Independent QA for this framework change itself.

Decision: one preapproved literal replacement in one explicitly classified
non-normative plain-text note. Solo, low-risk bounded Lean Build only; project
opt-in and work-item-bound contract must already exist in the claim's exact base
commit. The contract appears in approved scope and acceptance gate references.
Neither a small diff nor Agent-authored tests establishes eligibility.

Preserve the existing recoverable finish journal and diagnostic behavior. Add a
distinct completion classification, no Verifier handoff or Independent QA claim,
and no generic Build-to-Done edge. Unknown, drifted or unsupported inputs reject
without lifecycle mutation and keep ordinary verification available.

Acceptance: strict schema and exact-byte/diff checks, regular non-executable files,
base ancestry/current HEAD binding, no extra changed product files, immutable
approval inputs across recovery, disabled/missing opt-in, protected/indexed sources,
wrong actor, Standard/High-Assurance rejection, pending writes and replay behavior.
Test malformed and adversarial cases as well as valid completion through the CLI.
Full local verification, init/upgrade compatibility, documentation checks and
distinct reviewer acceptance precede PR. No new model calls, external release,
dependency, repository-wide migration or default policy activation.

Main risk: a human misclassifies a note that actually affects behavior. The checker
proves a declared exact transformation, never semantic harmlessness or authenticity
of the author's identity. Initial format/path limits deliberately narrow this risk.
If correctness cannot be preserved without broadening authority, retain ordinary
Lean and report the blocker rather than silently weakening its guards.

Documentation implementation also aligns the three root README entry points with
one short link/limitation, the docs index and ADR index. No Skill or project-owned
native instruction is modified or activated. Three new distributed files (the
checker, ADR and usage guide) account for the package inventory increase.
