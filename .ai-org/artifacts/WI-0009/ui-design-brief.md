# WI-0009 UI Design Brief

- UI delivery mode: code-first
- UI owner position: UI Designer
- Agent Identity: Yuna
- Surface: existing local Control Plane Dashboard
- Medium: executable HTML/CSS/JavaScript generated by Temple

## User need

A person watching Temple develop itself must immediately distinguish completed organizational work from work waiting to start. The page must also remain available while optional runtime telemetry is connecting or degraded.

## Changes

- Add a `Terminal` operational metric.
- Show `terminal` as a settled green badge on completed and cancelled Work Items.
- Preserve the existing compact two-column layout and responsive behavior; do not add another long section or vertical workflow.
- Continue to show Codex provider readiness or degradation separately from repository truth.

## States to verify

- Eight completed Work Items and one current Work Item do not inflate the queued count.
- A completed Work Item displays `terminal` and its canonical lifecycle state.
- The Dashboard loads while Codex history synchronization is incomplete.
- Provider offline or degraded state does not hide repository Work Items.
- Mobile-width and desktop-width layouts retain readable metric wrapping.

## Evidence requirement

Code-first delivery requires focused rendering assertions plus a runtime self-host snapshot. No external design tool or `ui_ref` is required. The Release Gate must retain runtime visual evidence and the exact candidate revision.
