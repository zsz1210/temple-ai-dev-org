# Product specification — WI-0133

## Problem

WI-0132 showed that two explicit bounded tasks passed under every tested route, yet native Lean Temple used 77.94% more aggregate operational Tokens than the responsible conventional Terra baseline. The measured Temple context was about 15.4 KB per case: 9.35 KB of always-on project instructions and about 4.4 KB of routed context. The deterministic retriever also selected unrelated Skills from generic tokens such as `md`, `no`, `task`, and `change`.

Temple cannot claim an efficient Lean path while it injects organization-wide explanation and false-positive capability suggestions into small implementation work. It also needs a next-run decision vocabulary that can describe secondary efficiency evidence without rewriting a completed protocol.

## Intended users

- A solo developer using several AI Agents on bounded repository work.
- A team that needs the same authority and evidence rules without forcing every task to load the entire organization manual.
- A maintainer evaluating Temple with reproducible, claim-bounded evidence.

## Required behavior

### Always-on project instructions

The distributed Temple instruction block must remain sufficient to route an Agent into the repository-backed workflow while becoming materially smaller than the WI-0132 baseline. It must retain these always-on invariants:

- repository files and Evidence are canonical; chat memory and titles are not state;
- Position, Agent Identity, Assignment, Human Principal, and authority remain separate;
- the repository-pinned Temple launcher owns supported lifecycle mutation;
- scoped work begins with a bounded Context Capsule and reads only routed sources;
- affected-path overlap, claims, workers, and integration ownership govern concurrent work;
- specifications, external trackers, Learning, and generated views retain their distinct authority;
- external, costly, irreversible, release, privacy, and exceptional policy actions require their governing approval;
- UI, High-Assurance, pilot stop, Developer/Independent-QA separation, and project-owned upgrade boundaries remain enforceable;
- deeper mechanics remain discoverable in `TEMPLE.md` and repository Skills.

The instruction block must not demand that every already-scoped task pre-read every project registry before resolving its Context Capsule.

### Deterministic capability retrieval

- Generic control words, common file extensions, and path names must not create lexical matches.
- A Position match is a ranking boost, not independent evidence that a Skill is relevant.
- Exact capability ID, meaningful title, tag, description, explicit Work Item, phrase, or pinned matches remain usable.
- A relevant documentation or domain query must still find its matching Skill.
- No semantic model, embedding service, or external dependency is introduced.

### Future decision semantics

- WI-0132 retains its frozen v2 analysis unchanged.
- A separately versioned decision contract may classify a ceiling comparison as `promising-efficiency` only when objective quality is non-regressing, blind quality is within the declared non-inferiority bound, and both operational Tokens and latency improve by pre-registered thresholds.
- The classification has zero routing authority and requires broader matched qualification.

### Small A/B confirmation protocol

- Compare responsible conventional Terra medium with optimized native Lean Temple Terra medium.
- Use the two corrected WI-0132 cases, four isolated candidates, and one arm-neutral Terra high evaluator.
- Retain zero retry, zero fallback, zero reroute, no candidate network, matched product inputs, held-out acceptance tests, and score freeze before unseal.
- Derive reactive ceilings from WI-0132 observations and record the formula.
- Remain `generation_ready: false` until a fresh Provider handshake and exact owner approval exist.

### Learning and documentation

- Capture one low-confidence Lesson limited to explicit low-risk bounded implementation work.
- Do not create a Practice or Skill from two cases.
- Update the English, Japanese, and Traditional Chinese Roadmaps consistently.
- Add the completed result and planned confirmation to the validation index without implying statistical qualification.

## Acceptance criteria

1. The distributed instruction block is smaller than 9,350 UTF-8 bytes and automated tests preserve every named invariant above.
2. The generic WI-0132 bounded query returns no unrelated capability; `checkout documentation` and explicit capability queries still retrieve the correct Skill.
3. Context measurement reports component bytes, shares, and avoidable retrieval reasons without estimating Provider Tokens from bytes.
4. Frozen WI-0132 output remains byte-identical; new decision semantics are separately versioned and regression-tested.
5. The four-candidate A/B protocol passes provider-free validation and cannot authorize or start generation.
6. A compact WI-0132 evidence bundle and scoped Lesson are retained without raw prompts, responses, hidden reasoning, credentials, or private project data.
7. Trilingual planning documents and the validation index accurately distinguish completed diagnostic evidence from future qualification.
8. Focused tests, complete repository verification, schema validation, Doctor, and distinct Independent QA pass.

## Excluded

- Running the A/B confirmation.
- Automatic or adaptive routing execution.
- Changing model defaults beyond the already accepted shadow policy.
- Management Console work.
- Public release, push, merge, or GitHub settings.
