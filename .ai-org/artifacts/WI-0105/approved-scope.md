# WI-0105 approved scope

## Purpose

Qualify the current local evidence for five organization-scale operating boundaries without pretending that deterministic fixtures are a real company deployment.

## Evidence classes

Every reported result must use one of these labels:

- `verified-local`: exact-revision executable behavior on this machine;
- `simulated`: executable behavior with synthetic identities, repositories, providers, or approvals;
- `documented-policy`: a repository contract that was inspected but not exercised in its real environment;
- `not-run`: no qualifying observation exists;
- `not-applicable`: outside this Work Item.

`verified-local` and `simulated` never imply real multi-human, multi-machine, external-service, production, regulated, or security-certification evidence.

## Boundaries

1. Collaborative governance: sponsorship, membership, claim eligibility, identity verification, recovery, and the distinction between automated, simulated, and real collaboration.
2. Tracker coordination: field ownership, team-visible parent versus internal child work, inspect/plan/reconcile behavior, and zero external write authority.
3. UI delivery: `code-first`, `preview-first`, `design-led`, and `not-applicable` gate behavior, including runtime visual-review requirements and vendor neutrality.
4. SRE and Security: current Observer, condition, audit, backup, privacy, command, and release safeguards versus the absent production on-call, incident, vulnerability-management, threat-model, and security-certification operation.
5. High-Assurance: human sponsorship, separation of duties, exact evidence, risk-scaled rollback, and distinct approvals versus the retained real drill.

## Execution

- Run only deterministic repository-local tests and read-only inspections.
- Build one machine-readable matrix from the exact candidate, named test results, canonical status, and retained validation records.
- Measure elapsed time and selected test counts. Leave unavailable values unknown.
- Do not contact Jira, Asana, GitHub Issues, Figma, production systems, or another machine.
- Do not create a Human Principal merely to make the current Solo project look Collaborative.
- Do not add SRE or Security Positions during this validation; report their current absence and retained design question.
- Do not start the optional Console, Observer service, Usage Collector, Docker, Colima, or a model turn.

## Stop conditions

Stop on a failing focused test, canonical schema failure, ambiguous evidence class, external write requirement, accidental credential or personal-data exposure, or any attempt to promote a simulated result into a real-environment claim. No automatic retry is allowed.

## Acceptance

The retained result identifies the exact Temple revision, commands, elapsed time, evidence class, current coverage, and named `not-run` gaps for all five boundaries. Developer and Independent QA remain separate Agent Identities. The result makes no production, enterprise, regulated, cost, Token-savings, security-certification, or external-service claim.
