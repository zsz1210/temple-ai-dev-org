# Representation comparison plan

Status: designed, not executed. Implementation and local regression testing are authorized. No live protocol has been prepared or consumed. The project usage policy requires a configured budget for automatic model execution; its current cost budget is null. Previous WI-0210 approval is not transferable.

Question: does removing duplicated acquisition measurement rows from the same task material reduce observed operational Tokens or delivery latency without reducing quality or increasing rereads?

Use four independent fresh deliveries, each with a Builder and distinct Verifier: full, model, model, full. All eight stages use gpt-5.6-terra with requested medium reasoning, the same frozen candidate and the same existing synthetic order-service task, acceptance checks, product oracle, common process-v9 prompt and task-material selection. Only the context entry format changes. Do not compare a changed prompt against the historical v8 prompt as a representation effect. Ordinary delivery is not a new arm in this narrowly causal diagnostic; it remains historical context only.

Retain the existing runtime isolation, command allowlist, exact candidate checks, account preflight, source and request digests, independent readiness review and immutable evidence seals. Extend the harness explicitly for the new schema and format; do not disable its schema checks to make a run pass. Probe both formats through the real sandbox without model generation before freezing readiness. The model view must actually be observed or the treatment is not established. No retries, fallback models, additional judge, reset, purchase or refill.

Proposed envelope, requiring approval: eight stages, 80,000 operational Tokens and six minutes per stage, 640,000 operational Tokens and 48 minutes aggregate. These are stop ceilings inherited from the previous bounded stage design, not a forecast or financial limit. WI-0210's slim delivery averaged 109,264.5 operational Tokens and 256.3 seconds across two deliveries; four similar deliveries would be approximately 437,058 Tokens and 17.1 actor minutes if representative, which is not guaranteed. Check current allowance without converting remaining percent into Tokens. Stop on missing usage, uncertain termination, candidate drift, failed quality, outside-scope access or a ceiling.

Report each stage and delivery: objective quality, added regression coverage, effective model acknowledgement, requested/observed effort with unknowns explicit, operational/input/cached/output Tokens, actor and total elapsed time, complete entry bytes, unchanged emitted body bytes, read command volume, test reruns, retries, interventions and treatment adherence. No per-command inference Token attribution is available. Two deliveries per arm and uncontrolled cache cannot establish statistical superiority. A neutral or adverse result must be reported, not rerun until favorable.

Stop after the four deliveries or the first safety/quality/budget failure. Freeze evidence, compare paired order and averages, explain limits, then recommend keep/adjust/revert. Do not promote the optional format to default based only on byte reduction.
