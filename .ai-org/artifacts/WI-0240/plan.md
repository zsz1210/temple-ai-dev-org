# Bounded continuity Git reads

The maintainer approved the preceding profiling recommendation: replace per-file Git blob subprocesses in continuity candidate verification with bounded batches, preserve every content and safety check, compare performance, run full verification and obtain distinct independent acceptance. Baseline: `860344965b36a95714fd0087f2148b8f2b23d1dd`. Prior unchanged profiling found 2403 binary Git reads taking 57.040 seconds; those observations are diagnostic rather than a guaranteed saving.

Scope: scripts/continuity-fixture.mjs, a small coordinator-only scripts/continuity-git-blobs.mjs helper, relevant tests and evidence. No initialization caching, policy, production evidence module, actor/provider behavior, test discovery, timeout changes, merge, publication, live model calls or account polling. Standard workflow, standard risk, offline experiment-verifier implementation. Developer Rikku; distinct QA Lulu; Principal human.

Design: read at most 16 exact blob OIDs per synchronous cat-file batch. Validate the entire binary response before returning any bytes: successful process, bounded output, expected OID/order and blob type, safe size bounded per blob, exact byte framing and no trailing output. Maximum raw blob is 1 MiB for disk comparison, 64 KiB for extracted candidate inputs; process timeout remains 15 seconds. Only one working-file batch is retained at a time. Read each actual disk file and recheck its safe file/link/mode/size status before comparison. Retain tree inventory, hidden/untracked/missing/unsafe checks, exact revisions, delivery records and independent candidate execution. No cross-call disk cache or verdict reuse. Invalid/partial batch output rejects the candidate with the existing caller failure category; no partial success.

Acceptance: retain all original 33 continuity results; cover real binary/empty blobs and chunk boundaries, bounded malformed/failed batch rejection and actual dirty/unsafe file rejection without candidate execution. Preserve the existing init/history/claim/finish/oracle assertions. Confirm no body changes to original tests except imports if required. Run focused controls, one exact-candidate profile using the same retained profiler, one final npm run verify, independent source/adversarial review, Doctor and evidence-only fast checks. If a defect appears, repair within this approved scope and revalidate the changed candidate; do not bypass the failed evidence. Do not duplicate a full run without a new behavioral change or unresolved concern.

Performance interpretation: direct subprocess counts are structural evidence. The retained baseline and candidate focused profiles are sequential observations on the same Node version, not randomized statistical proof; compare matching phases and disclose load. Final full-suite time is a new observation, not a controlled comparison with a differently loaded historical run. Stop after accepted local implementation and report, with rollback by reverting the scoped reader/helper/tests and rerunning full verification.
