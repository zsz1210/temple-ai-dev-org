# WI-0061 work order

## Outcome

Prepare the smallest trustworthy instrumentation pilot that can answer whether Temple can correlate one real Codex execution to its project, Work Item, task, Position, Agent, revision, requested/effective model, reasoning effort, outcome, and provider-reported Token usage.

## Stop boundary

This Work Item produces a proposal and an explicit human decision boundary only. It does not:

- create the synthetic repository;
- create or continue a Codex task;
- make a model request;
- create the later coordinator, Catalog, Orders, or Notifications repositories;
- use GitHub, hosted CI, another machine, company data, deployment, or release;
- enable automatic model routing or fallback.

## Why one repository first

The existing multi-repository plan requires trustworthy task-level measurement before four repositories can produce meaningful effectiveness data. A one-task pilot isolates observer readiness and provider correlation from federation and contract complexity. Failure remains useful evidence and stops the larger rehearsal.

## Human decision required

The repository owner must approve or revise the exact path, model/reasoning profile, Token ceiling, wall-clock ceiling, disk ceiling, retry rule, and stop conditions before execution begins.
