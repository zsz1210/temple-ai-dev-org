# Instruction-induced work audit

## Outcome and scope

This audit completes approved step 3. It inspects the generic entry instructions, distribution TEMPLE.md, temple-work entrypoint and Lean/assurance references, plus the frozen delivery comparison prompt. It is not a full audit of every optional Skill, a model forward test, or evidence that the revised instructions save Tokens.

## Findings and disposition

| Surface | Avoidable work or ambiguity | Disposition |
| --- | --- | --- |
| Distribution TEMPLE.md startup | A long list of project records qualified only by “as relevant” can be interpreted as a universal checklist. | Replaced with operation-specific routing. Tracker, retrieval and telemetry settings are not universal startup reads. Governing requirements still override routing. |

## Machine validation versus model material

WI-0206 allows omission of a whole body only with an exact caller declaration that the unchanged whole body is already read and remains available in the current context. WI-0207 optionally projects recognized actor inventories and indexes only non-current gate references. Original acquisition, safety, freshness and actor checks still run. Instructions, approval, scope, risk and current required evidence remain model-readable bodies. Unknown shapes or extra reasons preserve the source.

The options are deliberate opt-ins, not new mandatory startup commands. An explicit full-source instruction still requires that source. No automatic instruction-residency detector, profile downgrade or unseen-source cache is introduced.

## Evidence and next boundary

One synthetic large-roster fixture emitted 66,956 -> 56,735 source-body bytes and 90,323 -> 80,156 serialized JSON bytes before final verification. This is a fixture measurement, not measured inference consumption or proof of faster delivery. Fixed-candidate verification records supersede these preliminary numbers if the fixture changes.

No model comparison was run. A future test should isolate unchanged baseline, availability reuse, task material and instruction effects rather than attribute the whole difference to routing. Preserve quality, elapsed delivery and observed Operational Tokens as separate outcomes; include actual required reads and report failures. That experiment is outside steps 1–3.
