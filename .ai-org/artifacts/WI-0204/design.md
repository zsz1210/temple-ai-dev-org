# Leaf authority and cancellation repair

Generation is disabled in this successor. It cannot run a real Provider through runSubject until native prevention has been validated and independently reviewed; fake-Provider tests remain available.

Parent orchestration is moved out of universally inherited developer instructions and into the root turn input. The shared instructions define only authority boundaries: a delegated leaf must perform its brief directly and never delegate. Forks remain fresh/no-history. This removes contradictory inherited imperative instructions, but request composition alone cannot prove model adherence.

The current official configuration reference documents agents.max_concurrent_threads_per_session, not a max_depth key. Do not invent or silently configure an unsupported depth option. A one-spawned-thread session limit is a candidate prevention control, not yet proof of no grandchildren; its runtime behavior must be established before lifting the generation guard.

Reference: https://learn.chatgpt.com/docs/config-file/config-reference.

Interrupted and failed terminal events may have unfinished tracked items. Record those terminal observations with unfinished-item counts; only successful completion requires every tracked item closed. This improves cancellation evidence without promoting interrupted work into successful delivery or claiming terminal state for unvalidated actors.
