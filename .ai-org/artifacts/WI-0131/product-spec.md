# Product specification — WI-0131

## Outcome

Temple must be able to run a trustworthy follow-up experiment that answers three separate questions:

1. Does a native Lean Temple process improve delivery over a responsible conventional workflow on the same Terra route?
2. Does escalating a semantically ambiguous bounded task from Terra medium to Luna max improve the quality/resource trade-off?
3. Does Sol xhigh add enough quality over Luna max to justify treating it as the capability ceiling for consequential work?

## Corrected comparison

| Arm | Process | Route | Purpose |
| --- | --- | --- | --- |
| A | Responsible conventional workflow | Terra medium | Baseline |
| B | Native Lean Temple workflow | Terra medium | Isolate process effect |
| C | Same Lean Temple workflow | Luna max | Efficient deep-reasoning escalation |
| D | Same Lean Temple workflow | Sol xhigh | Flagship capability ceiling |

B/C/D are route-bundle comparisons because model and reasoning effort vary together. A later matched-effort experiment is required before attributing a difference to the model alone.

## Acceptance contract

Every case must explicitly classify identity/reference semantics, input immutability, idempotency, compatibility, and error semantics as `specified` or `not-applicable`. An `unknown` dimension is a preflight blocker. Hidden tests may enforce only specified contract behavior.

## Evidence boundary

This Work Item prepares and verifies the experiment without model generation. A separate exact owner approval is required for the live matrix. Results remain diagnostic until sample sizing is derived from corrected-pilot variance and representative task families are tested.
