# Work Order — WI-0016

## Outcome

Complete the local Phase 4A durability operations around the existing content-addressed backup and transactional restore core.

## Approved scope and design

1. Add deterministic backup-set inspection and retention planning under an explicit caller-provided backup root.
2. Separate retention planning from application. Applying a plan requires its digest and explicit consent; stale plans fail closed.
3. Refuse symbolic links, special files, unsafe names, nested project paths, and any deletion target outside the resolved backup root.
4. Add a versioned audit export containing bounded canonical events and recovery metadata. Reapply field and value redaction at export time.
5. Exclude prompts, responses, hidden reasoning, credentials, provider payload bodies, and runtime secrets from the export contract.
6. Add post-upgrade rollback and interruption-boundary rehearsals that operate on disposable project copies, never the primary worktree.

## Verification

- Unit tests cover retention ordering, preservation rules, stale plans, path traversal, symlinks, and partial failures.
- Audit-export tests cover recursive redaction, bounded event selection, deterministic content, and excluded runtime bodies.
- Existing backup, restore, upgrade, schema, and Doctor behavior continues to pass.
- A disposable data-bearing project exercise records exact before, upgraded, rolled-back, and recovered digests.

## Risk review

The highest risk is unintended deletion or disclosure. Retention defaults to preview-only, requires a digest-bound apply step, preserves an explicit minimum, and has no implicit default root. Audit export is a narrow allow-listed projection, not a repository archive.

## Stop condition

Stop after the local capabilities and disposable recovery rehearsal are independently reproducible. Broader operating systems, production disaster recovery, and regulated-auditor acceptance remain explicit external validation.

## Rollback

Revert the Phase 4A implementation commit. Existing backup manifests remain readable and existing restore behavior remains the fallback.
