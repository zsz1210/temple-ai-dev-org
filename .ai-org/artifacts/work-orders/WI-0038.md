# Work order — WI-0038

## Purpose

Make lifecycle gates fail closed after a real WI-0034 transition accepted an `EVID-*` placeholder that did not exist in the normalized evidence registry. The historical event remains auditable; this correction prevents recurrence.

## Technical design

- Treat any gate reference beginning with `EVID-` as an intended normalized Evidence ID, even when its suffix is malformed.
- Before a transition writes the Work Item or event stream, load the evidence registry once and require every such reference in the merged gate evidence to exist, belong to the same Work Item, and remain unexpired and uninvalidated.
- For `independent_qa_pass`, allow repository artifact paths for backward-compatible Solo workflows. When the reference is a normalized Evidence ID, require a `test` or `runtime` entry with outcome `pass`.
- Preserve the stricter revision, actor, risk, and kind contracts already applied by High-Assurance mode.
- Reject before any canonical mutation so the Work Item and event stream remain byte-identical on failure.

## Risk review

This tightens lifecycle acceptance without changing normal evidence recording. The main compatibility risk is incorrectly treating ordinary documentation paths as normalized evidence, so validation is limited to strings beginning with `EVID-`. Existing file-backed Solo gates remain supported. Registry reads must not create or mutate project state during a failed transition.

## Verification

- Reproduce the malformed and nonexistent placeholder case.
- Reject an Evidence ID belonging to another Work Item.
- Reject failed, expired, and invalidated Independent QA evidence.
- Prove each rejection leaves the Work Item and event stream unchanged.
- Prove current same-Work-Item pass evidence still advances the gate.
- Run the full repository verification gate.
