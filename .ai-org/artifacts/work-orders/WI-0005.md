# WI-0005 Work Order and Technical Design

- Status: approved
- Approved at: 2026-08-30
- Engineering owner position: Tech Lead
- Implementation owner position: Developer
- Approval source: project owner approved completing the revision-aware evidence fix

## Outcome

Preserve historical evidence after legitimate repository evolution without weakening artifact integrity. Evidence bound to an exact Git revision must be checked against that revision; evidence artifacts created after the candidate revision must remain protected against current-file drift.

## Acceptance criteria

1. A Git-tracked artifact is validated against the content at the evidence entry's exact `scope_revision`.
2. Later commits may change that tracked path without invalidating the historical evidence.
3. A digest that disagrees with the recorded revision still fails `temple doctor`.
4. An artifact absent from the recorded revision falls back to current-file validation so post-revision observations and reports remain tamper-evident.
5. A missing scope revision or missing fallback artifact produces an actionable failure.
6. Existing drift detection remains covered and the full repository suite passes.
7. The current Temple repository returns a clean `temple doctor` result after the fix.

## Technical design

- Keep the evidence schema unchanged.
- For each evidence entry with a non-null `scope_revision`, verify that the commit exists before validating its artifacts.
- For each artifact, ask Git whether the path exists as a blob at that revision:
  - if it exists, hash the blob bytes and compare them with the recorded digest;
  - if it does not exist at that revision, validate the current repository file as before;
  - if Git reports that the revision is unavailable or a known blob cannot be read, fail instead of silently falling back.
- Evidence without a `scope_revision` continues to use current-file validation.
- Keep invalidated evidence integrity-checkable; invalidation changes gate eligibility, not historical tamper detection.

## Test design

- Retain the existing test proving that an untracked/post-revision artifact drift fails Doctor.
- Add a regression test that records a tracked artifact, advances the repository with new content at the same path, and expects Doctor to pass.
- Mutate the recorded digest and expect Doctor to fail against the historical blob.
- Replace the exact revision with a syntactically valid but unavailable commit and expect an actionable Doctor failure.
- Run the focused evidence test file, full suite, current-repository Doctor, and Independent QA from a detached worktree.

## Risk review

- **False fallback:** never use the working-tree file when Git confirms that the artifact existed at the recorded revision.
- **Missing history:** fail explicitly when the recorded commit is unavailable instead of treating the working tree as equivalent evidence.
- **Binary artifacts:** hash raw Git blob bytes, not decoded text.
- **Regression in post-revision evidence:** keep current-file validation for observations or reports created after the candidate commit.
- **Scope expansion:** do not add evidence invalidation commands, schema fields, migrations, or unrelated Observer behavior.

## Exclusions

- No evidence registry rewrite or deletion of historical entries.
- No schema or migration change.
- No change to gate eligibility, expiry, or invalidation policy.
- No external release or version bump.
