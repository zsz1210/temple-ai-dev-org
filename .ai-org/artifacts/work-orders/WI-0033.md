# Work order — WI-0033

## Purpose

Define an operator-owned trust boundary for credential-bearing or executable providers before implementing another provider startup path.

## Required decisions

- Whether checked-in configuration may nominate a provider while an operator-local approval pins its exact digest, or whether all executable provider configuration is operator-local.
- How approved GitHub Enterprise API origins are identified and rotated without allowing arbitrary origins.
- How a repository refers to a credential handle without naming arbitrary ambient environment variables.
- How Codex executable path and arguments are pinned, reviewed, and invalidated after repository or binary changes.

## Fail-closed baseline

A repository alone must never cause Temple to read an arbitrary ambient secret, send a bearer token to an unapproved origin, or spawn a repository-selected command. No implementation enters Build until this contract is approved.
