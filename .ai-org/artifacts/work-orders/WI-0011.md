# Work Order — WI-0011

## Outcome

Qualify the Codex usage sources that Temple can observe today and ship the first truthful live-telemetry preflight. The result must distinguish exact active-thread usage from account-wide activity, repair the terminal-task subscription error, and refuse to invent project or Work Item attribution.

## Evidence entering Design

- Official OpenAI App Server documentation lists `thread/tokenUsage/updated` as a notification for the active thread and documents version-specific schema generation with `codex app-server generate-json-schema`.
- The locally bundled Codex CLI is `0.150.0-alpha.12.2`. Its generated `ThreadTokenUsageUpdatedNotification` schema matches Temple's current `threadId`, `turnId`, `tokenUsage.total`, `tokenUsage.last`, and `modelContextWindow` parser shape.
- The read-only `account/usage/read` endpoint is available for the current Codex-backed authentication and returns account-level summary fields plus daily buckets. The diagnostic retained field names and availability only, not account values.
- Temple's retained journal has no `org.temple.codex.usage.updated.v1` observations.
- The only registered Codex task is `task-0001`, status `completed`, attached to terminal `WI-0008`. The Provider reads its bounded history and then incorrectly attempts `thread/resume`, which returns `-32600` and degrades the Dashboard.

Official protocol source: <https://developers.openai.com/codex/app-server/>

## Deliverables

1. Classify registered tasks into history-reconcilable, live-resumable, and terminal groups with one shared, tested status contract.
2. Reconcile terminal task history without attempting a live resume and without degrading an otherwise healthy Provider merely because terminal work cannot resume.
3. Send the documented `initialized` notification after a successful App Server `initialize` request.
4. Add a read-only `temple usage preflight` command that reports task topology, provider capability and readiness, observed detailed-usage coverage, attribution qualification, and the next honest action.
5. Require an explicit `--probe-codex-account` flag before calling `account/usage/read`.
6. Retain only the account endpoint's availability, returned field names, bucket availability/count, request latency, and scope label. Do not retain lifetime or daily Token values in project state or CLI output.
7. Label account usage `account-wide` and `unallocated`; it cannot populate the project baseline or any Work Item, Position, Agent, task, model, price, cost, quality, or outcome dimension.
8. Keep automatic recommendations, model switching, price lookup, spending, and lifecycle authority disabled.
9. Publish the behavior as the next alpha with focused tests, user guidance, architecture notes, and a bounded validation record.

## Preflight states

Detailed active-thread usage uses these states:

- `observed`: at least one detailed usage event exists.
- `awaiting-observation`: a live-resumable registered task exists, but no detailed usage event has arrived.
- `no-live-registered-task`: only terminal/setup/history task topology exists.
- `provider-unavailable`: the Provider registry reports an unavailable capability or connection.

Baseline qualification remains `not-qualified` unless detailed observations carry a Work Item and task correlation. Account-wide totals never change that result.

## Verification

- Pure tests for completed, archived, setup, active, waiting, and attention task topology.
- Provider integration tests proving terminal tasks are read but not resumed and live tasks retain the resume path.
- Preflight tests for no journal, detailed observations, provider absence, account-probe success, and account-probe failure.
- Assertions that no raw account Token value, prompt, hidden reasoning, credential, price, cost, or automatic routing action appears in output.
- Full `npm run verify` at the exact candidate revision and Independent QA from a fresh detached worktree.

## Exclusions

- No new Codex task or model turn is created for measurement.
- No account-wide number is stored, displayed, subtracted, or assigned to a project.
- No claim of Token savings, cost savings, per-Work-Item efficiency, or baseline completion.
- No automatic model recommendation, routing, provider switching, alert budget, external notification, publication, or deployment.
- No private Codex session-file scraping or unsupported internal-database dependency.

## Rollback

Revert the candidate commit. The preflight is read-only, and generated/runtime state below `.git/temple/` remains disposable; canonical Work Items and Evidence Registry entries keep their existing authority.
