# WI-0003 Work Order and Design

- Status: approved
- Approved at: 2026-08-30
- Product and documentation owner position: Product Manager
- Implementation owner position: Developer
- Approval source: project owner requested a final README article-layout pass

## Outcome

Make the public entry point feel deliberately edited rather than merely complete. Preserve every accepted capability boundary while improving first-screen recognition, section rhythm, scan paths, and quick-start progression.

## Acceptance criteria

1. The first viewport presents the name, framework category, promise, language switcher, current alpha boundary, CI status, runtime requirement, and license without a dense paragraph wall.
2. Major sections have consistent visual separation and a short orienting sentence where needed.
3. Quick start is divided into three numbered actions.
4. Collapsible scenarios remain native GitHub Markdown/HTML and readable on narrow screens.
5. No custom CSS, fixed-width layout, decorative screenshot, or unsupported capability claim is introduced.
6. English, Japanese, and Traditional Chinese keep the same section, divider, callout, scenario, and quick-start structure.
7. Repository checks and local Markdown links pass.

## Content design

- Replace the plain title block with a centered, accessible hero using GitHub-supported HTML.
- Keep one CI badge and compact text links for Alpha, Node.js, and MIT instead of adding a decorative badge wall.
- Add restrained horizontal separators between the major reading acts: problem, scenarios, adoption, evidence, and reference material.
- Preserve the current information order and all evidence limits.
- Convert Quick start into `Install → Initialize → Start the first Work Item` substeps.
- Keep tables only where they communicate exact Position and profile mappings.

## Risk review

- **HTML portability:** use only common GitHub README elements and meaningful alt text.
- **Translation drift:** make structural changes to all three files in the same patch and compare heading/subheading counts.
- **Visual clutter:** limit the hero to one status badge and three compact metadata links.
- **Claim drift:** do not edit capability, validation, SRE, Security, or human-authority meaning during the layout pass.

## Exclusions

- No logo or image generation.
- No product or framework capability change.
- No documentation-site work.
- No release publication or tag.
