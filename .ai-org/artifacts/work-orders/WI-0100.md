# WI-0100 work order

## User decision

Temple Core must remain complete without a Management Console, Usage Collector, or always-on Observer. The Management Console is an optional human-facing tool for developers who want a browser view. Detailed Token observation is also optional and must not require the Console.

## Product boundary

| Capability | Default | Responsibility | Runtime authority |
|---|---|---|---|
| Temple Core | available | Work Items, lifecycle, evidence, context, collaboration, and CLI | canonical repository state |
| Management Console | off | read-only human view of canonical state and retained telemetry | no lifecycle mutation and no telemetry writer lease |
| Usage Collector | off | explicit on-demand Codex usage capture into clone-local telemetry | telemetry observation only |
| Managed-local collection | off, experimental | optional background form of the Usage Collector | telemetry observation only |

## Required behavior

- `temple console start` serves the existing human-facing interface only after explicit invocation.
- Starting the Console does not attach Codex, start the repository polling provider, install a service, acquire the telemetry writer lease, or enable command routes.
- The Console may run while a separate Collector owns the telemetry writer lease. File-change invalidation prompts bounded snapshot refresh without a permanent repository scan loop.
- `temple usage collect` connects the configured Codex Provider and writes retained telemetry without opening an HTTP listener.
- Stopping either optional process leaves Temple Core and retained observations usable. Missing observation remains unknown rather than zero.
- The existing combined `control-plane start` path remains available for compatibility during this change, but new documentation directs ordinary users to the split commands.
- The macOS managed-local service launches the Collector only. It does not implicitly expose the Console on loopback, LAN, Tailscale, or another interface.

## Acceptance and evidence

The four acceptance criteria in `.ai-org/work-items/WI-0100.json` govern delivery. Verification must include runtime evidence that the read-only Console and the Collector can coexist, the Console does not grow the telemetry journal while idle, the Collector opens no HTTP listener, existing telemetry survives shutdown, and the full repository suite remains green.

## Exclusions

- no public release, tag, package publication, repository visibility change, or deployment;
- no automatic model routing or cost claim;
- no redesign of Management Console screens;
- no promise that unobserved historical Work Items can be backfilled;
- no optimization claim for WI-0094 until separate measurements prove it.
