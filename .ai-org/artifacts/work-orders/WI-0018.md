# Work Order — WI-0018

## Outcome

Implement Phase 4C federation so several authoritative repositories can expose a bounded read-only portfolio without centralizing lifecycle authority.

## Approved scope and design

1. Add a project-owned participant registry with immutable participant project IDs, repository paths, expected revisions, and optional freshness limits.
2. Represent cross-project identities with composite references. Bare Work Item IDs are never accepted as globally unique references.
3. Add versioned Initiative, dependency, API contract, event contract, compatibility, and rollout-wave references.
4. Read participant state without writing to it. Validate project identity, schema, source revision, and freshness before projecting status.
5. Project missing, stale, invalid, identity-mismatched, or unreadable participants as `unknown` with bounded diagnostics.
6. Exclude credentials, Human Principal details, raw evidence bodies, business-source bodies, prompts, and provider payloads.
7. Model incompatible changes as explicit compatibility and rollout waves; never imply an atomic multi-repository commit.

## Verification

- Unit tests use isolated repositories and cover healthy, missing, stale, invalid, identity-mismatched, and malicious participant inputs.
- Read-only tests hash participant repositories before and after portfolio generation and prove no lifecycle mutation.
- A disposable multi-repository rehearsal covers an owned contract, a consumer dependency, compatibility states, and rollout waves.
- Independent QA reproduces the rehearsal from a fresh checkout of the exact candidate.

## Risk review

The central risk is authority leakage. Federation reads allow-listed summaries only, resolves repository roots safely, never imports credentials or full evidence bodies, and exposes no transition, approval, closeout, release, or external-write operation.

## Stop condition

Stop after the isolated multi-repository rehearsal is reproducible. Real multi-human, multi-machine, protected-branch, hosted CI, and production rollout evidence remains external until directly executed.

## Rollback

Revert the Phase 4C implementation commit. Participant repositories remain unchanged because the portfolio path is read-only.
