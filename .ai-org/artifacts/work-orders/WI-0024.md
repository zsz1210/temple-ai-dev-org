# Work order — WI-0024

## Accepted scope

Make current Doctor validation fail closed when a restored project contains legacy or missing CLI bootstrap metadata. Preserve strict bootstrap validation for current installations and do not silently upgrade, mutate, or adopt the restored project.

## Acceptance criteria

- `runDoctor()` returns a deterministic unhealthy or upgrade-required diagnostic instead of throwing for the exact restored Alpha.5 AiPet lock shape.
- Current valid bootstrap metadata still passes.
- Malformed present metadata still fails strict validation.
- Focused and full verification pass, followed by fresh Independent QA at an exact revision.

## Technical design

Treat the absent `cli_bootstrap` document as invalid-but-bounded input at the validator boundary. Return validation errors that Doctor can report through its normal result rather than dereferencing an absent document. Add the smallest regression at the closest bootstrap/Doctor test boundary and reuse the real legacy shape where practical.

## Risk review

The main risk is weakening current launcher trust checks. Tests must distinguish missing legacy metadata from malformed present metadata, and must retain repository-local CLI path, digest, symlink, and repository-spec validation. No primary AiPet checkout may be mutated.

## Rollback

Revert only the validator and regression-test commit. The already verified backup and restore primitives remain unchanged.
