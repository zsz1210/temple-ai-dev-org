# Work order — WI-0036

## Purpose

Let an authenticated device on the same private Tailscale network observe the live Temple Dashboard without converting the loopback Human Inbox or Agent Command prototype into remote control.

## Approved scope

- Keep the Temple control-plane listener on `127.0.0.1`.
- Add an explicit private-viewer request class for one exact configured HTTPS host behind a trusted local reverse proxy.
- Require Tailscale's injected user identity header for private-viewer requests.
- Return a redacted projection that excludes the Human Inbox, Agent Commands, daemon filesystem details, and raw journal events.
- Give the private viewer a refresh-only event stream; never forward raw SSE journal records.
- Refuse all private-viewer mutations and all untrusted Host values.
- Provide an optional Tailscale Serve launcher that checks the installed CLI version, configures tailnet-only HTTPS Serve, and never invokes Funnel.
- Preserve the full loopback Dashboard and its existing local mutation defenses.

Remote Agent Commands, task creation, model selection, secrets, public internet access, LAN-wide binding, tailnet policy mutation, and automatic startup are outside this Work Item.

## Technical design

The HTTP listener classifies each request as either `loopback`, `private-viewer`, or `untrusted`. Loopback requests keep the current behavior. Private-viewer requests must arrive at the exact runtime-configured host, include a non-empty `Tailscale-User-Login` header injected by Tailscale Serve, and reach the backend through its localhost-only listener.

The private viewer receives a Dashboard rendered without a session secret or interactive Inbox sections. Its snapshot is derived from the normal snapshot but drops `daemon`, `inbox`, and `recent_events`, and replaces authority metadata with an explicit read-only viewer contract. Its event stream carries only a refresh signal and cursor; the browser fetches a new redacted snapshot. `GET /api/v1/inbox` and every non-GET request are denied for the private-viewer request class.

The optional launcher detects the current Tailscale DNS name and exact CLI version, starts Temple on an ephemeral loopback port, and then configures `tailscale serve --bg` for that port. The validated integration version is Tailscale `1.98.8`; no package is vendored. Shutdown removes only the Serve mapping created by the launcher and closes Temple.

## Risk review

- A tailnet is private transport, not proof that every member should see project metadata. The setup guide must call out Tailscale grants and the default allow-all policy risk.
- Tailscale identity headers are trusted only because the backend remains on localhost. Direct LAN or tailnet binding stays forbidden.
- The remote projection must not contain command capability, complete instructions, local paths, or raw telemetry records.
- Serve and Funnel use related commands. Temple must invoke only `tailscale serve`, inspect the resulting configuration, and fail closed if it cannot prove a tailnet-only HTTPS route.
- Process lifetime is operational state. Automatic login startup is deferred until a separate persistence and recovery design exists.

## Dependency and license review

Temple does not add a runtime package dependency or redistribute Tailscale. The optional adapter executes a user-installed Tailscale CLI at the exact validated version `1.98.8`. The open-source Tailscale client is BSD-3-Clause licensed. Tailscale account, network, and service terms remain the operator's responsibility.

## Verification

- Unit-test request classification, exact Host matching, missing/spoofed identity, redaction, refresh-only SSE, and rejection of remote Inbox and mutation routes.
- Unit-test launcher parsing and command construction without changing a real tailnet.
- Run the full local verification suite.
- Start the real local Dashboard, configure Tailscale Serve, and verify HTTPS health, redacted snapshot, missing command surface, rejected POST, and live refresh from the private URL.

## Rollback

Clear the specific Tailscale Serve HTTPS mapping, stop the Temple control-plane process, and remove the private-viewer runtime option. The canonical `.ai-org/` state and generated telemetry remain intact.
