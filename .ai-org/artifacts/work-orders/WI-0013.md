# Work Order — WI-0013

## Outcome

Make Temple's toolkit self-host mode bind its repository launcher to the current checkout. A fresh detached worktree must execute that worktree's own `bin/temple.mjs` by default, so a same-version global or linked package cannot silently substitute code from another revision.

## Evidence entering Design

- WI-0012 Independent QA passed the exact candidate only after setting `TEMPLE_CLI_PATH=./bin/temple.mjs`.
- Without that override, the detached worktree's launcher resolved the globally linked same-version Temple package from the primary checkout.
- The existing bootstrap validates a version but does not distinguish two checkouts carrying the same version.
- `temple.lock.installation.mode` already distinguishes `toolkit-self-host` from an ordinary installed project, and `installation.source_overlay` identifies the self-host overlay boundary.

## Approved scope and design

1. Return both bootstrap and installation metadata from the launcher lock reader.
2. Preserve an explicitly supplied `TEMPLE_CLI_PATH` as the highest-priority compatible override.
3. In `toolkit-self-host` mode, resolve `bin/temple.mjs` below the launcher's own repository root, canonicalize both paths, and reject any missing file or path escape.
4. Verify the repository-local CLI reports the lock's exact version before invoking it.
5. Fail closed on an invalid self-host boundary; do not fall back to npm or a globally linked package.
6. Keep ordinary installed projects on the existing version- or revision-pinned package runner path.
7. Install the managed launcher change into this repository through the normal self-host upgrade path so `temple.lock` retains an exact checksum.

## Risk review

- A launcher path check must be based on canonical paths so a symlink cannot escape the repository.
- Self-host detection must require the explicit installation mode and expected overlay contract; ordinary projects must not start depending on repository source files.
- The version check remains necessary even for a local path because a stale or partially upgraded checkout must stop rather than run mixed framework versions.
- `--bootstrap-info` remains a read-only bootstrap inspection and should not require the local CLI to be executable.
- No package publication, deployment, push, external write, model switch, or spending is authorized.

## Verification

- Add launcher-fixture tests proving local self-host execution without `TEMPLE_CLI_PATH`, version-mismatch refusal, missing-file refusal, and canonical-path escape refusal.
- Preserve the ordinary init launcher and explicit override coverage.
- Run the focused runtime-coordination suite and full `npm run verify` at the exact candidate revision.
- Create a fresh detached worktree at that candidate, run `npm ci`, rerun the full suite, then run `node ./templew.mjs doctor . --json` without `TEMPLE_CLI_PATH`.

## Rollback

Revert the candidate commit. The previous explicit `TEMPLE_CLI_PATH=./bin/temple.mjs` workaround remains available for exact-candidate self-host verification.
