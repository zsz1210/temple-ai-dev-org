# Work order — WI-0037

## Purpose

Make the documented private Dashboard stop path truthful after three real PTY `Ctrl-C` rehearsals left the Temple-owned Tailscale Serve mapping behind and exited the project launcher with status 1. The third rehearsal proved that a safe core CLI is insufficient when the version-pinned `templew.mjs` parent exits before its child finishes cleanup.

## Technical design

- Install `SIGINT` and `SIGTERM` handlers as a latch rather than one-shot listeners.
- Keep both handlers installed throughout Tailscale Serve reset and Control Plane shutdown so a repeated terminal signal cannot restore Node's default exit behavior during cleanup.
- Make the latch idempotent, report the first signal only, and expose explicit disposal for tests and final process teardown.
- Replace the launcher's synchronous child boundary with an awaited child process. Keep parent signal handlers installed while it runs and forward `SIGINT`/`SIGTERM` so both terminal process-group delivery and direct launcher signals reach the core CLI without terminating the parent early.
- Preserve the existing exact-configuration ownership check; never reset a pre-existing or unrelated Serve configuration.

## Risk review

The core change affects only shutdown sequencing after an explicitly enabled local private viewer. The launcher change applies to every version-pinned command, so it must preserve the child exit status and dispose its forwarding handlers on normal exit and spawn failure. The main risk is swallowing later signals indefinitely, so both parent and child handlers must be removed after their resources settle. Cleanup failure must remain visible as a nonzero CLI exit instead of being reported as success.

## Verification

- Unit-test first and repeated `SIGINT`/`SIGTERM` behavior with an isolated signal emitter.
- Integration-test direct signals to the project launcher with a child that completes delayed cleanup and preserves exit status 0.
- Re-run the complete private-viewer and CLI suites.
- Start the real tailnet-only viewer, send `Ctrl-C`, verify exit status 0, verify `tailscale serve status --json` is empty, and verify the old loopback port is closed.
