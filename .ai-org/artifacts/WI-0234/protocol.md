## Interpretation fixed before generation

This is diagnostic, not calibrated optimization. Report correctness first and
cost/time separately. There is no approved numerical exchange rate between avoided
errors and Tokens: therefore a mixed quality/resource tradeoff cannot authorize a
default change. Equal quality with higher overhead does not support adopting Temple
for this shape. A correctness improvement without worse measured resource use is
a candidate for further investigation, not statistical proof. Report every pair,
all-attempt totals, missing data and excluded coordination/review costs. Do not
extend the sample to rescue an unconvincing result.

## Instrument and launch conditions

Implement the actual named-permission thread/turn route, independently review it,
and run offline verification before spending any approved subject call. Freeze
source, config, fixture and request digests before the first turn. Both actors must
have isolated repositories and no access to coordinator answers or sibling data.
Use a separate read-only packaged Temple runtime, not a read grant to this source
checkout (which contains the oracle). Disable inherited memories, hooks, MCP,
plugins, apps, browser and agent delegation and inspect effective configuration.
Preserve provider model/effort acknowledgements, usage, first-stop and cleanup.
An unqualified actual tool surface is a validity blocker, not a passing sandbox.

Do not mutate frozen prior experiments. Actor-local failures may leave incomplete
pairs; shared isolation, privacy, missing usage or cleanup uncertainty stops the
whole run. No automatic model retry after a repair. Account percentages cannot be
converted to this Token budget. No-generation readiness work is not a model sample.
