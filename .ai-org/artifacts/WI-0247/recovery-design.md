# Bounded diagnostic reconciliation

The human authorized repairing the applied-finish recovery path and then resuming
WI-0246 verification. No merge, release, new provider calls or broader policy
change is authorized. Existing Solo attributed approval remains separately recorded.

## Contract and design

- Add an explicit `work-item finish-recover` preview/apply command, not automatic
  fallback in `finish`. Require an approval artifact and exact preview fingerprint.
- Support only fully applied, failed Developer Lean finish records with an
  unclaimed Test item, no workers, ordinary Solo responsibility and no UI. Terminal
  acceptance, partial lifecycle journals and unified/mechanical delivery are excluded.
- Preserve the original journal, receipt, handoff and lifecycle bytes. Write a
  separate recovery artifact and retain the previous failed diagnostics. Recovery
  repairs diagnostic bookkeeping only; it never supplies Test acceptance.
- Require original candidate ancestry, unchanged committed and working product
  scope, exact current item/handoff/receipt, and append-only event history.
- Current actor must remain eligible. Drift is limited to referenced evidence
  and the exact legacy Solo to explicit attributed migration; all other bound
  policy, assignment and schema inputs remain exact. Reference changes
  are listed as changed evidence, not accepted as independent review.
- Bind current snapshot, approval bytes, original record and Git HEAD to a preview.
  Recheck after diagnostics and before persisting; stale/failed diagnostic output
  cannot settle recovery. A crash after writing the recovery artifact may resume
  only the same fingerprint. Never delete the prior journal or rewrite a receipt.

## Verification and risk

Standard workflow. Regression tests must reproduce administrative HEAD advance,
evidence amendment and explicit compatible policy migration. Negative tests cover
dirty/changed product, receipt or item drift, non-prefix events, policy weakening,
stale preview, missing approval, active workers, partial journal and interrupted
artifact persistence. Full offline verification and distinct review are required.
No warning is globally ignored. Original failure remains inspectable after recovery.

The README candidate is unchanged. The new recovery implementation has its own
candidate and independent verification before applying the new command to WI-0246.

Packaging integration: `scripts/check-package.mjs` needs its reviewed file ceiling
raised by exactly two, from 444 to 446, for the new runtime module and operator
guide. No dependency, allowlisted root, privacy exclusion or byte limit changes.
This supporting path has no overlap with WI-0246's README scope and is included in
the full candidate review.

## Independent-review corrections

The first candidate failed independent adversarial review despite 1,262 passing
offline tests. Bind original scope, complete inputs and output paths to the plan
digest in the unchanged canonical receipt. Validate a persisted crash artifact's
clean diagnostic shape and original-record binding before any settlement writes
and again during subsequent reads.

Allow unrelated worker/reservation entries only with original candidate Git bytes
whose SHA-256 matches the original bound input. Preserve this item's entries and
all non-entry registry fields exactly; current actor and active-target checks stay.
If the original bytes are not provable, fail closed. This narrow compatibility rule
does not permit changing global resource definitions or project authority.
