# Reliable evaluation and input-overhead audit

## Authorized outcome

The maintainer authorized one consolidated improvement phase following the
WI-0236 review. Repair the instrument, qualify it offline, and audit actual input
obligations before deciding whether another model comparison is worthwhile.
This is not authority to rewrite sealed results, change a model, remove assurance,
purchase Credits, reset usage, publish, merge around review, or start open-ended
experiments. No new live batch is enabled by this design alone.

## Contract decisions

- Keep the reported product candidate separate from a later delivery-record commit.
  Preserve exact candidate testing. A descendant may add only bounded records for
  the assigned item; every non-record byte/mode must remain identical. Validate
  the current item, released claim, matching handoff and cited evidence. Do not
  accept arbitrary files merely because their parent is `.ai-org`.
- Keep historical exact-HEAD qualification as the default offline oracle behavior;
  use an explicit new record-descendant option in the new protocol. Retired
  approvals cannot launch the changed protocol. Original WI-0236 stays sealed.
- Share the existing sequence's typed assessment/continuation decision between
  runners; do not import its artificial command permission policy into native
  execution. Genuine product or administration failure can be a case-local result
  only after candidate/isolation/cleanup/accounting validation. Unknown impact,
  source drift, invalid revision, privacy and runtime failure remain batch stops.
- Observe one supported native shell wrapper without executing it. Attribute only
  bounded literal single commands; complex scripts stay unknown. Report coverage
  and bytes, not inferred per-command Tokens or proof of reading. Reject editing
  flags from the reading category. Retain no raw command or output in the aggregate.

## Acceptance and stop criteria

1. Reproduce the record-only descendant using the real installed claim/finish CLI,
   then prove unchanged product acceptance plus rejection of changed product,
   tests, unrelated history, stale/missing evidence and arbitrary record paths.
2. Replay native shell formats, unknown compound commands, duplicate events,
   absent outputs and editing flags. Qualify observation usefulness independently
   from product success; unit-test counts alone never qualify an experiment.
3. Prove local failure continuation and mandatory shared-stop decisions on the
   same helper used by live orchestration, without provider generation.
4. Audit required sources, emitted outputs and repeated work against retained
   WI-0236 evidence. Separate byte counts, provider Tokens and causal uncertainty.
   Retain only a reduction that preserves authority and demonstrates a meaningful
   structural removal. Do not invent an arbitrary statistical threshold.
5. Run complete offline verification on the final behavioral candidate; give a
   report with explicit live-comparison go/no-go. If no justified high-impact
   treatment exists, stop with that finding rather than spend another model batch.
