# Alpha.30 candidate freeze

## Candidate identity

- Version: `0.1.0-alpha.30`
- Proposed tag: `v0.1.0-alpha.30`
- Distribution direction: source-first through GitHub; npm deferred
- Repository state during this freeze: private
- Exact technical candidate: the implementation commit containing this record, resolved and retained by `WI-0163`
- Exact-package qualification: reserved for `WI-0164`

This record freezes an internal candidate identity. It does not publish a package or authorize any external release action.

## Supported claim

Temple is a repository-native, human-directed operating framework for organizing AI-assisted development with durable Work Items, explicit responsibilities, evidence gates, recovery, learning, and explainable advisory execution routing.

The claim describes shipped operating capability. It is bounded by repository checks, clean-room AI-assisted use, multi-repository rehearsals, privacy review, and Independent QA records.

## Included candidate scope

- repository-backed responsibility, Work Item, evidence, recovery, and learning contracts;
- staged context routing and capability discovery;
- advisory execution routing that explains a suggested model and reasoning level without launching work;
- Solo, Collaborative, and High-Assurance organizational profiles;
- local multi-repository federation and coordination boundaries;
- deterministic verification, Independent QA separation, and release gates;
- optional read-only Management Console and Usage observation surfaces; and
- human-facing documentation for AI-assisted initialization and operation.

## Explicit non-claims

- No guaranteed Token, cost, latency, or productivity savings.
- No automatic model selection, model switching, Provider execution, or spending authority.
- No production, regulated, enterprise-wide, broad multi-machine, or broad multi-company qualification.
- No claim that an unaided first-time human can operate Temple without AI assistance.
- No requirement to install the Management Console, Usage Collector, semantic retrieval, or another optional integration.

## Freeze and qualification boundary

`WI-0163` verifies the version identity, claim boundary, repository checks, and one exact technical candidate. `WI-0164` must build and qualify the package archive from that exact commit. If qualification requires a source change, the candidate must be replaced explicitly and reverified; qualification cannot silently patch or repoint it.

Historical Alpha.29 records remain evidence for their named revisions only. They do not qualify this candidate.

## Publication boundary

The following remain separate Human decisions and are not authorized by this record:

- changing repository visibility;
- creating or pushing the tag;
- creating a GitHub Release;
- enabling or publishing to npm;
- deploying a hosted service; or
- announcing the release or making stronger outcome claims.
