# Context Capsule successor evaluation design

- Work Item: `WI-0144`
- Status: generation-free design; no successor Provider run is authorized
- Predecessor: `WI-0143`

## Why the successor is split

WI-0143 completed eight correct candidate turns with complete acquisition classification, zero retry, zero fallback, zero human intervention, and zero rework. It also produced different resource behavior by project shape:

| Project shape | Routed source bytes | Routed Operational Tokens | Routed latency | Interpretation |
|---|---:|---:|---:|---|
| Single repository | -63.79% | -13.28% | -16.27% | Promising descriptive signal |
| Multiple repositories | -65.51% | +31.01% | +1.70% | Unstable and unsuitable for a shared conclusion |

The frozen matched-cache rule failed in one pair for each shape: the maximum cache-share difference was 2.31 percentage points for the single-repository task and 11.15 points for the multi-repository task, above the two-point limit. The result therefore supports neither a causal Token-saving claim nor an automatic routing-policy change.

More repetitions of the same confounded multi-repository design would measure the confound more precisely. The next work must answer two different questions.

## Program A — single-repository maturation

### Decision

Determine whether Routed Context should become the default recovery context strategy for the tested bounded single-repository Task Shape.

### Hypotheses

- Quality: Routed Context must preserve the exact objective answer and required evidence acquisition.
- Efficiency: after the cache-control rule passes, Routed Context should reduce Operational Tokens by at least a predeclared minimum effect worth adopting.
- Operations: Routed Context must not increase retry, fallback, human intervention, rework, or route violations.

### Fixed factors

Hold the repository fixture, task contract, model, reasoning effort, tools, sandbox, output schema, quality oracle, and treatment packages constant. Change only the context-loading strategy.

### Assignment and cache control

Use independent matched blocks with randomized or counterbalanced treatment order. Retain gross input, cached input, non-cached input, output, Operational Tokens, cache share, latency, acquisition, and outcome for every arm.

Do not derive the confirmatory sample size from two pairs alone. Before generation, state:

1. the smallest Operational Token improvement worth changing the default for;
2. the acceptable false-positive and false-negative risk;
3. the cache-balance method and threshold; and
4. the pilot dispersion used by the chosen sample-size method.

If WI-0143 is insufficient to estimate dispersion, run a separately labelled bounded pilot and do not treat it as confirmation.

### Stop and interpretation

Stop on correctness failure, protocol drift, repository mutation, limit breach, retry, or fallback. A cache-control failure retains descriptive results but blocks the causal efficiency decision. A passing result applies only to the tested Task Shape and project evidence.

## Program B — multi-repository cache isolation

### Decision

Determine whether the multi-repository context package and acquisition structure are stable enough for a later routing-efficiency comparison.

### Redesign before generation

1. Separate invariant coordinator instructions from participant-repository evidence.
2. Use identical invariant prefix ordering across treatments where the task contract permits it.
3. Randomize treatment order across independent repository-set blocks instead of relying only on adjacent pairs.
4. Report block-level cache share and treatment-by-block interaction rather than only an aggregate mean.
5. Keep repository acquisition, source bytes, non-cached input, output, correctness, latency, intervention, and rework as separate measurements.
6. Prefer a Provider-acknowledged cache-disable or cache-key control only after the exact current interface is verified. Otherwise predeclare a matched-balance rule and keep failed blocks descriptive.

### Gate to a later efficiency experiment

Program B does not decide whether Routed Context saves Tokens. It qualifies the measurement design. A later comparison becomes eligible only when:

- every treatment package and repository set is frozen;
- the cache-control method is observable and predeclared;
- acquisition classification has no unknown or off-route reads;
- quality remains objective and primary; and
- the observed block design is stable enough to justify a sample-size calculation.

## Shared authority boundary

Neither program authorizes Provider generation, automatic execution, model fallback, purchased Credits, publication, or a routing-policy change. Each executable protocol needs a new Work Item, immutable digest, generation-free preflight, explicit account-impact envelope, and exact approval.

The retained WI-0143 report remains the source for predecessor measurements. Do not rewrite it when a successor changes the design.
