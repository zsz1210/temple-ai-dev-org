# Temple 產品 Roadmap

[English](roadmap.md) | [日本語](roadmap.ja.md) | **繁體中文**

Temple 是一套用來組織 AI 輔助軟體開發的運作框架。它讓人與 AI Agent 的責任清楚可見，把產品目標拆成範圍明確的工作，並將決策、證據與復原狀態保留在儲存庫中。

## 產品目標

讓不同規模的多 Agent 開發都能可靠運作：

- 個人開發者可以同時運用多個 AI Agent，又不會遺失脈絡或重複工作；
- 跨專業團隊可以明確分工，並安全地平行推進；
- 大型組織可以保留既有的儲存庫、規格、任務系統與批准流程。

Temple 會依工作本身調整流程。小型、可逆的變更維持輕量；一般開發保留必要審查；高風險工作才使用更嚴格的保證機制。

## 現有產品能力

| 能力 | Temple 目前提供的功能 |
| --- | --- |
| 開發組織 | 分離職位、Agent 身分、指派、權限與工作認領 |
| 交付流程 | 範圍明確的 Work Item、分級流程、交接、證據關卡、獨立 QA 與結案 |
| 工作延續 | 以儲存庫保存狀態、脈絡路由、Task 關聯、備份、復原與工程學習 |
| 團隊擴展 | 安全平行規劃、多人治理、外部任務系統邊界與多儲存庫協作 |
| 延伸能力 | 專案自有規格、UI 開發模式、Skill、Capability 與選用整合 |
| 執行建議 | 依步驟提供可解釋的模型與工具建議，並與責任及執行權限分開 |

Management Console、持續 Usage 觀測、語意檢索與 Provider 執行都屬於選用層；Temple 的核心組織不依賴它們。

## 產品里程碑

### 1. 開發組織基礎 — 已完成

- Position、Agent Identity 與 Assignment 契約
- 以儲存庫為核心的 Work Item 與生命週期
- 交接、證據、Independent QA 與結案邊界
- 安裝、升級、備份、還原與新 Task 脈絡復原

### 2. 團隊與專案擴展 — 已完成範圍性驗證

- 產品、UX、UI、API 與技術規格的權威來源管理
- Lean、Standard 與 High-Assurance Workflow Profile
- 安全平行規劃與執行協調
- 多人協作、外部 Tracker 對應與多儲存庫 Federation
- 受治理的 Skill 與 Engineering Learning Loop

真實的跨公司、多機器及受監管環境仍需進一步驗證。

### 3. 自適應執行 — 核心已完成，效果尚未取得合格證據

- 職責與模型選擇已經分離
- 同一個 Work Item 可依不同步驟解析不同執行設定
- 先檢查 Capability、隱私、風險、Provider 與資源限制，再考慮偏好
- 建議設定與實際觀測到的模型、推理強度分開保存
- Route 解析只提供建議，不會啟動 Provider 或變更專案狀態

下一個目標是用比較實驗確認：自適應路由在哪些工作比固定的安全設定更有效，又在哪些工作不值得使用。

### 4. 真實情境驗證 — 目前階段

- 驗證新使用者與全新 Agent 能否在沒有舊對話的情況下完成 Core Path
- 在任務、模型、工具與驗收條件相同時，比較 Temple 與一般可靠開發流程
- 在 Temple 流程不變時，比較 Adaptive Execution Route 與固定模型設定
- 驗證真實多人、多機器與多儲存庫開發
- 量測正確性、復原能力、重工、人工介入、Token、時間與運作負擔

這個階段只接受足以支持決策的證據。如果結果沒有改善或成本高於收益，就必須縮小適用範圍、簡化流程或移除無法證明價值的機制。

### 5. 生態系與公開發佈 — 未來

- 只有在信任、協議、權限及復原契約通過驗證後，才加入 Provider 執行
- 只有在大型儲存庫量出確實需求後，才加入語意或本地檢索
- 只有具備合格比較證據與安全 fallback 的任務類型，才考慮自動路由
- 持續改善選用的管理介面與整合，但不讓它們成為框架必要依賴
- 等擁有者重新啟動公開決策，且候選版本通過發布關卡後，再準備公開發佈
