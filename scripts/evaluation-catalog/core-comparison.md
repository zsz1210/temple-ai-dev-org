Both arms use the same complex, low-risk, reversible interruption-recovery product
task and common Terra Medium Verifier. Ordinary Codex is not in this cohort.
Both Temple variants must pin the same candidate framework revision so the finish
diagnostic fix is shared; comparing an old broken finish with a new core mode would
confound the mode comparison. This four-cell screen cannot establish statistical
superiority, reliable model routing or high-risk safety.

## Fixed task and outcome contract

Reuse the documentation-checker continuity material identified by the catalog.
Before launch, freeze a fresh unsolved product seed, approved task brief, exact
acceptance oracle, runtime/tool allowlist and transitive dependencies. Preserve the
same required behavior and forbidden changes across arms. Do not copy a previous
successful solution into the seed or use administration-only work as the product.

Proposed semantic interruption: after the first actual implementation candidate is
submitted for verification, before the Verifier runs. Save its exact revision and
available evidence, terminate the active implementation runtime with acknowledged
cleanup, then resume control in a fresh session. Recovery must locate that exact
candidate, determine the unfinished stage, arrange distinct verification and close
truthfully. If the arm never reaches that event, retain its failed/stopped outcome;
do not move the trigger to obtain a sample. This specifically tests delivery handoff
recovery, not recovery halfway through an arbitrary source edit.

The eventual adapter must demonstrate that this event has the same meaning in
both arms. Product workers must have equivalent allowed tools and prior-history
access. Core supplies one compiled work contract; current Lean supplies its actual
installed instruction/context route. Common coordinator, grading and restart costs
belong in both totals. The coordinator retains Temple authority in both arms.

Acceptance includes correct product behavior, completed actual verification,
exact candidate/evidence binding, preserved authority, no duplicate delivery,
truthful recovery and no prohibited external effect. Synthetic forbidden actions
must be detectable independently of what the participant reports. A successful
closeout record alone cannot pass the product oracle.

## Qualification before generation

1. Demonstrate a fresh correct-product positive control and known-wrong-product
   negative control. Verify installation and native instruction exposure from the
   actual adapter, including separate control/product checkout isolation.
2. Demonstrate the semantic interruption, acknowledged cleanup, recovery, failed
   diagnostics, repeated invocation without double dispatch, and stopped accounting.
3. Verify requested and effective models, effort, usage reporting, permission/tool
   enforcement, source hashes and exact instructions. Prompt byte counts and any
   tokenizer estimate remain distinct from observed provider usage.
4. Fill all eight phase reservations from relevant evidence: setup, implementation,
   verification, permitted repair, reverification, variability, usage lag and cleanup.
   Reserve outer coordination separately. Freeze repair allowance and aggregate
   token/time/call ceilings before dispatch; no arbitrary cap without buffers.
5. Freeze the existing execution protocol, source pins, run order/cache method and
   concrete launch scope. The current template leaves unknown values null. A preview
   that exits successfully does not satisfy any of these execution qualifications.

## Decision after the screen

First report product and recovery acceptance per cell, including all stopped/unrun
cells. Then compare gross/cached/net input, output, operational tokens, elapsed
delivery time, administration/context repetition, repair and human intervention.
Report both implementation and whole-delivery costs; never rank a partial delivery
as a cheaper success or attribute shared QA protection exclusively to one mode.

Advance the candidate to a larger matched cohort only if both candidate cells meet
the same product/recovery/authority criteria and the observations justify a specific
repeatable reduction in administrative work. Any material regression first becomes
a defect investigation. Mixed outcomes remain mixed. No numeric superiority
threshold or default change is inferred from four diagnostic cells.

Later small-task overhead, ordinary Codex versus Temple, before/after Temple and
high-risk synthetic comparisons reuse the catalog/selection/observation contracts.
Do not add them to this initial cohort or silently enlarge its budget. High-risk
fixtures need their own positive/negative controls and existing safeguards; this
low-risk prototype does not qualify them.
