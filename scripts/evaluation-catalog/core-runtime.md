# Qualified preparation for the selected core comparison

This repository-only adapter prepares the four cells selected by
[core-comparison.template.json](core-comparison.template.json). The mode labels are
current **coordinator-owned Temple Lean** and **Temple core candidate**. Both use
the same approved utility task, framework source and blind Terra Medium Verifier.
Current Lean retains its full installed instruction/context route; core receives
one compiled contract in a separate product checkout. This is not an ordinary
Codex comparison or a change to shipped Temple profiles.

New preparations use `real-doc-check-fixture-v5.mjs`. V5 retains V4 product,
reference, public-test and hidden-test behavior and adds an equal public
`node check-delivery.mjs` precheck to both modes. This standalone, generation-free
helper runs tests under an owned TMPDIR, records leftover files/directories/
symlinks and persistent workspace changes, and removes only its own temporary
area after preserving findings. It contains no oracle or reference solution.
Builders fix known findings before submission in their current turn. The blind
Verifier receives public check results, gathers all known defects, and still
independently challenges semantics. Coordinator acceptance requires mechanical
cleanup as well as the existing checks; recorded residue rejects delivery even
when ordinary test assertions pass. Process cleanup and test-file cleanup remain
distinct. Historical outcomes are never regraded into new successes.

V4 preserves the original
unsolved seed and public tests, and appends explicit acceptance boundaries to the
brief. These define option-key ownership across prototype chains, supported input
types, error precedence, lexical/real-path behavior and CLI diagnostics. The blind
reviewer receives the same boundaries and a matching review rubric. The five
product-mutant intents remain fixed; six additional reference-fault controls are
qualification-only. Historical v1/v2/v3 fixtures and runner imports remain unchanged.
Stopped protocols cannot resume against a changed source/acceptance hash; any
supplemental no-model regrade stays separate from their frozen outcomes.

The [settings file](core-runtime.settings.json) holds phase estimates, stop levels,
reserves and aggregate ceilings. Change settings and requalify/freeze before a new
run; do not change the executor merely to edit a numeric reservation. This adapter
deliberately validates only the selected four-cell protocol. Other catalog modes
remain separately qualified adapter work, not silently enabled combinations.

## Preparation and execution

Use the explicitly qualified self-contained Node.js runtime on macOS. The existing
installed-provider adapter rejects unsupported linked runtimes instead of expanding
filesystem access. Paths, binary SHA-256 values and effective settings are recorded
in the private prepared protocol.

```sh
node scripts/core-comparison-fixture.mjs prepare
node scripts/core-comparison-fixture.mjs step /absolute/prepared/lab /absolute/approved-record.json PROTOCOL_SHA256
```

`prepare` makes exclusive isolated fixtures, runs real installed-provider command
and empty-thread controls and seed/reference/mutant oracles, then writes a private
protocol and a **pending** approval record. It never sends `turn/start`.
The exact approved protocol and account-impact boundary must be supplied before
`step` can generate. Each `step` runs at most one model turn. Invoke a new process
for the next step; after Build, the actual handoff checkpoint binds the previous
process identity, exact candidate, evidence digest, cell and contract. Recovery in
the same process is rejected. A record left running is ambiguous and cannot retry.

The first authorized subject is also the native model-tool canary. Command probes
and empty configured threads do not prove model-driven tool use. Any unexpected
tool, fallback, permission, usage, cleanup or source failure stops the cohort and
preserves unrun rows. There is no extra unbudgeted canary, reset or retry.

The deterministic coordinator commits product changes, records Developer evidence,
calls the pinned finish CLI, then grades the exact product before the existing
distinct Verifier turn. The reviewer remains blind to mode, model and execution
history. A reference-baseline failure supplies only the names of failing added
tests, not hidden acceptance or the reference implementation. The reviewer must
identify every failed test and quote the shared contract to classify an assertion
as exceeding an explicit requirement. That classification requires a failing
review and permits product-test repair; it never accepts or waives a submission.
An unresolved/reference defect or incomplete qualification still stops the cohort.
The pregrade is bound to stage, protocol, candidate and product digest and is
checked after review; no extra model turn or second oracle run is introduced.
The sole repair uses a new evidence filename; retired rejected evidence is never
overwritten and reused as the new Developer gate. A second product rejection stays
rejected without falsely closing the Work Item. Failed diagnostics remain visible.

Returned bounded actor counters are saved before product/Git postprocessing. A
later inspection failure remains stopped with the original call and an explicit
known operational-token lower bound; successful-phase reservation counters alone
are not a whole-cost report. The core adapter also requires added regression tests
to pass the correct reference and detect at least one of the five seeded mutants.
It retains all five results. A qualified reference and each of the five mutation
controls must actually execute a positive integer number of tests. An ordinary
empty added-test suite remains a repairable product rejection; equal counts,
universal mutant detection and a ban on skipped tests are not imposed.
Zero detections is a product rejection. Invalid,
timed-out, cancelled or incomplete qualified controls stop the instrument; an
unqualified reference also stops unless the failing review qualifies every failed
added assertion against the explicit contract as described above. A repair must
pass normal reference and mutation qualification before acceptance. Historical
graders and their results are unchanged.

## Repeatable generation-free rehearsal

```sh
node scripts/core-comparison-fixture.mjs prepare-rehearsal
node scripts/core-comparison-fixture.mjs rehearse-step /absolute/rehearsal/lab
```

Repeat `rehearse-step` in fresh processes until completed or stopped. The first two
cells deliberately submit an incorrect product to exercise actual CLI rework and
reverification for both modes; the third submits an overspecified root-code test
to exercise contract qualification and test repair; the fourth exercises first-pass
closeout. The
actor is a deterministic test double, while installation, Git, lifecycle, oracle
and restart operations are real. These are not model observations or performance
results. An offline-rehearsal protocol is rejected by the live actor adapter.

## Reservation and interpretation

Authorized repair-and-continue work can use an explicit successor. The predecessor
remains immutable. The bounded successor adapter carries its accepted GPT-6/core
sample and exact Lean Build, records the failed recovery and all prior usage, and
copies isolated control/product trees before starting only unfinished stages.
Its provenance is an intervention, not a newly randomized clean four-cell run.
Before each call it reserves the whole remaining repair/reverification path against
the user's cumulative ceiling. Unknown usage, changed candidates or broader drift
cannot use this timestamp-only recovery route.

Lean recovery uses a stage-local diagnostic gateway: Status, Context and Observe
always use no-write; Doctor and discovery are read-only; mutating commands and
outside targets are denied. The normal launcher and installed framework defaults
remain unchanged outside that recovery copy. Protected byte checks still apply;
this gateway is not a general sandbox against arbitrary participant file writes.
Actual CLI tests and the injected rehearsal execute default Status through this
gateway, rather than assuming a simulated actor proves diagnostic side effects.

Per cell, the complete five-turn capacity is 640000 Operational Tokens: the prior
same-fixture buffered 620000 path plus 20000 cleanup reserve. Four cells plus
200000 outer reserve total 2760000; at most 20 model turns. With no repair, each
cell uses only Build, recovery and Verify. Each generation phase has an expected
amount, higher reactive stop and still higher lag reserve. Planned time capacity
is 47 minutes per cell plus 10 minutes outer reserve, totaling 198 minutes of
reservations. The adapter enforces actor phase limits and per-cell actor-time
capacity; it does not enforce an end-to-end batch wall deadline across coordinator
operations or gaps between processes. Report actual elapsed delivery separately.
Required repair/reverification capacity stays reserved before starting earlier
phases. The aggregate time field is a reservation ceiling, not a wall-time promise.

The old same-fixture observations were roughly 104000 operational-token lower
bounds per cell, not GPT-6 variance estimates or guaranteed new costs. Observed
completed-turn counters, gross/cached input and output stay separate. An interrupted
or failed turn has incomplete accounting and cannot become a cheap success. The
outer coordinator reservation is not a measured counter or a provider billing
guarantee; outer Tokens and Credits remain unknown unless actually observed.
Private paths, approved task contracts and bounded result records stay in the
exclusive lab; do not publish raw protocol/account records.

Read the [comparison contract](core-comparison.md) for acceptance, decision rules,
cache limitations and the distinction from later ordinary/Temple or version tests.
